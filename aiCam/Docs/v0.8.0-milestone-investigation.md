## Issue #479: VRoid撫で肩問題

### 概要
VRoidアバターをロードした際に肩のボーンが落ち込む（沈む）問題。

### 関連ファイル

| ファイル | パス | 役割 |
|---------|------|------|
| RuntimeFBXLoaderBridge.cs | Assets/Scripts/FBXLoader/Core/ | VRM 0.x/1.0統合ローダー |
| RuntimeHumanoidAvatarBuilder.cs | Assets/Scripts/Avatar/ | ボーン調整・左右補正 |
| FbxCoordinateSystemDetector.cs | Assets/Scripts/FBXLoader/Utilities/ | VRoid座標系検出 |
| VRMLoaderFromStreaming.cs | Assets/Scripts/VRMLoader/ | StreamingAssets VRM読み込み |
| AvatarDiagnostics.cs | Assets/Scripts/Avatar/ | ボーン診断ツール |

### 現状の実装

#### VRoid特有の処理（FbxCoordinateSystemDetector.cs）
- VRoidアバターは RootNode に Y=180° 回転を持つ
- プロファイルタイプ: `FBXProfile.VRMStyle`
- 変換行列: `Scale(-1, 1, -1)` を適用（X軸とZ軸反転）

#### ボーン補正機能（RuntimeHumanoidAvatarBuilder.cs）
- `EnsureLeftRight()`: 左右ボーン補正機能（行262-332）
- Hipsのローカル座標系を基準に左右判定
- 肩ボーンも処理対象: `HumanBodyBones.LeftShoulder` / `RightShoulder`

### 推定原因

1. **座標系変換の不完全性**: VRoidのY=180°回転に対するX軸反転が不完全
2. **ボーン階層のY軸問題**: Hipsに対する相対位置計算でY軸の符号が逆になる可能性
3. **SkeletonBone生成時の補正不足**: 回転補正がHips回転による子ボーンへの影響を考慮していない
4. **VRM 1.0での Humanoid設定**: 肩ボーン定義がUnity Humanoidと異なる可能性

### 対応方針
1. `FBXImportLogs`内のVRM読み込みログを確認して肩ボーン座標値を検証
2. `AvatarDiagnostics`で肩ボーンの回転状態を確認
3. `GenerateSkeletonBones()`での肩ボーン親の回転影響を追跡

## Issue #477: ピンチ/タップ/スワイプのUI入力衝突

### 概要
ジェスチャー操作中に意図しない入力が同時発火する問題。

### 関連ファイル

| ファイル | パス | 役割 |
|---------|------|------|
| PlaceAvatarOnPlaneOnly.cs | Assets/Scripts/ | メインの入力ハンドリング |
| VrmHitDetector.cs | Assets/Scripts/Expression/ | VRMヒット検出 |
| CameraCaptureController.cs | Assets/Scripts/UI/ | UI判定 |
| UIToolkitInputBlocker.cs | Assets/Scripts/UI/ | 入力ブロッカー（スタブ） |

### 現状の入力検出優先度（PlaceAvatarOnPlaneOnly.cs Update）

```
1. touchCount == 2 → HandlePinchScale()
2. touchCount == 1 && CameraLocked → HandleLongPressDrag()
3. touchCount == 1 && Off → HandleOffModeRotation()
4. touchCount == 1 && (PlaneLocked || CameraLocked) → HandleSwipeInteraction()
5. touch.phase == TouchPhase.Began → タップ処理
```

### 検出された問題点

| # | 問題 | 原因 |
|---|------|------|
| 1 | ピンチ中の指離脱で予期しないタップ | touchCount: 2→1への遷移でスワイプハンドラが起動 |
| 2 | スワイプ中の微動でタップ判定 | タップ距離閾値とスワイプ判定の分離不足 |
| 3 | UI判定の重複チェック | EventSystemが複数回実行される |
| 4 | VrmHitDetectorのシングルタップ無視 | ダブルタップ待機中に何もできない |

### 改善案

1. **ジェスチャー状態のEnum導入**: 現在のジェスチャー状態を明示的に管理
2. **タップ/スワイプ閾値の明確化**: `tapDistanceThreshold`(20px)の厳格な適用
3. **UIToolkitInputBlockerの実装**: スタブから実際の実装への移行
4. **状態遷移ガードの強化**: フレーム間の状態遷移を適切にハンドリング

## Issue #476: Lighting/Shadow Panel Closeボタン貫通

### 概要
パネルのCloseボタン押下時にタップがアバター設置として認識される。

### 関連ファイル

| ファイル | パス | 役割 |
|---------|------|------|
| LightingPanel.uxml | Assets/UI/CameraCapture/ | パネルUI定義 |
| LightingPanel.uss | Assets/UI/CameraCapture/ | パネルスタイル |
| CameraCaptureController.cs | Assets/Scripts/UI/ | HideAllPanels(), IsPointOverUIPanel() |
| LightingPanelController.cs | Assets/Scripts/UI/Lighting/ | パネル制御 |
| PlaceAvatarOnPlaneOnly.cs | Assets/Scripts/ | IsTouchOverUI() |

### UI貫通発生のフロー

```
[T] Closeボタン(×)をタップ
    ↓
[T+0] ClickEvent発火
    ├─ HideAllPanels()実行
    │  └─ lightingPanelOverlay.RemoveFromClassList("visible")
    │     → display: none に変更
    └─ フレーム終了
    ↓
[T+Δ] Update()実行 (PlaceAvatarOnPlaneOnly)
    ├─ IsPointOverUIPanel()
    │  └─ ClassListContains("visible") → FALSE（既に削除済み）
    └─ IsTouchOverUI() が FALSE を返す
       → アバター配置ロジックに進む [BUG]
```

### 推定原因

1. **レイアウト計算の遅延**: CSS `display`変更は次フレーム以降に適用
2. **イベント処理順序**: ClickEvent直後にUpdate()が実行される
3. **ClassListContains判定のタイミング**: パネル非表示処理と入力判定のタイミングのズレ

### 対応方針

1. パネル非表示後に一定フレーム（例: 2フレーム）入力をブロック
2. `isClosingPanel`フラグを導入してタップを無視
3. `PointerUpEvent`でのみパネルを閉じるように変更

### ダブルタップ検出ロジック（行1983-2028）

```csharp
void OnTopButton3Click()
{
    expressionTapCount++;
    if (expressionTapCount == 1)
    {
        expressionTapCts?.Cancel();
        expressionTapCts = new CancellationTokenSource();
        HandleExpressionTapAsync(expressionTapCts.Token).Forget();
    }
}

async UniTaskVoid HandleExpressionTapAsync(CancellationToken ct)
{
    await UniTask.Delay((int)(DOUBLE_TAP_THRESHOLD * 1000), cancellationToken: ct);

    int finalTapCount = expressionTapCount;
    expressionTapCount = 0;

    if (finalTapCount >= 2)
    {
        // ダブルタップ → リセット
        ResetExpression();
    }
    else
    {
        // シングルタップ → 次へ
        SwitchToNextExpression();
    }
}
```
